scores = q @ k.transpose(-1, -2)
scores = scores / math.sqrt(q.shape[-1])
weights = (scores + mask).softmax(axis=-1)
weights.realize()   # tinygrad runs work only when a result is needed

in tinygrad these lines are lazy: each one adds to a graph. nothing is computed until a result is needed (realize(), .numpy(), .item()…)

run here on a tiny example so the generated code fits: q, k of shape (1, 4, 4), so d = 4 and the scale is ÷ √4

tinygrad builds a lazy graph, schedules work, generates code, and executes it
PyTorch: eager operations dispatch to implementations; optional compilation can optimize larger regions
one Python line need not mean one kernel: 2 lines → 1 kernel, 1 line → 3 kernels
our first lab device is CPU. the tensor mathematics stays the same

with Context(TRAINING=1):
    optimizer.zero_grad()
    logits = model(tokens)
    loss = logits.sparse_categorical_crossentropy(
        targets
    )
    loss.backward()
    optimizer.step()

lab setup · 2 of 4

run the setup helper

from the project folder. one command, then read what it prints

mac · Terminal
bash setup-mac.sh

uses .venv/bin/python if it exists, otherwise python3.12

windows · PowerShell
.\setup-windows.bat

uses .venv\Scripts\python.exe if it exists, otherwise py -3.12

what the helper does, in order (it prints each step)

  1. validate the five configuration templates runs check_configs.py
  2. check the CPU compiler finds clang and runs clang --version
  3. create or reuse .venv a Python 3.12 environment for this project only. an unrelated .venv is left untouched
  4. install the exact package version pip install -r requirements.txt into .venv
  5. run the diagnostic check_environment.py: computation, gradients, attention, an optimizer update → SETUP OK

if it ends with SETUP FAILED: fix the prerequisite it names, then rerun the same command. no existing environment is deleted
