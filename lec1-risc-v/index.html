what a cpu does, forever

  1. read the instruction at the address in pc (the program counter)
  2. do it
  3. pc += 4 (every instruction is 4 bytes), repeat

our program: add up 8 numbers

    .data
nums:
    .dword 3, 1, 4, 1, 5, 9, 2, 6    # 8 numbers, 8 bytes each
total:
    .dword 0                         # the answer goes here
 
    .text
    .globl _start
_start:
    la   t0, nums                    # t0 = address of nums[0]
    li   t1, 8                       # t1 = how many are left
    li   t2, 0                       # t2 = sum so far
loop:
    ld   t3, 0(t0)                   # t3 = the number t0 points at
    add  t2, t2, t3                  # sum += it
    addi t0, t0, 8                   # point at the next one (8 bytes on)
    addi t1, t1, -1                  # one fewer left
    bne  t1, zero, loop              # any left? go again
 
    la   t4, total
    sd   t2, 0(t4)                   # total = sum
    ebreak                           # print the registers: t2 should be 31
 
    mv   a0, t2                      # exit code = the sum
    li   a7, 93                      # syscall 93 is exit
    ecall
  1. .data: the numbers, in memory. a label names each address
  2. .text: the instructions. the cpu starts at _start
  3. t0 = where we are in the array, t1 = how many are left, t2 = the sum
  4. the loop: load a number, add it, move to the next, count down, go again
  5. store the sum in total. ebreak shows us the registers
  6. ask the os to exit, with the sum as the exit code: a7 = 93 (exit), then ecall

  • every ld asks memory for something. a 4 GHz cpu does an add in 0.25 ns; ram takes ~70 ns to answer. ~300 adds' worth of waiting
  • so the chip keeps copies of recently used memory close by: caches. l1 is tiny and fast, l3 bigger and slower, then ram
