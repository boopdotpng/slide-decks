why it’s hard

what makes tenstorrent hard

the chip

120 cores, 1.5 mb of sram eachno cache. kernels copy every byte in and out themselves
5 programs per coremove in, unpack, math, pack, move out. they have to agree
sync by handa missing wait is a fast wrong answer. a buffer that never frees hangs the card

the software

163 repos, 28 archivedseveral ways in from pytorch, some already dead
2.4 million linesand that’s before llvm, built from source at one pinned commit
~40 min first buildlinux only. the docs are mostly the source code

so we wrote our own: blackhole-py skips almost all of it

how to work · live

learning a kernel nobody taught you

examples/common/copy_tile.ttrv from blackhole-py, pasted into an ai

replay copy_rows {
    repeat r in 0..8 { math.mova2d dst[r * 8], src=r * 8 }
}
 
// Copy the next SrcA tile into Dst tile t.
macro copy_tile(t) {
    tensix.stall math, srca_vld|sfpu
    math.rwc reset
    math.cfg dst_offset=t * dst.tile
    replay.run copy_rows
    tensix.stall sync, math
    math.cfg dst_offset=0
    math.rwc reset, release=a
}
  1. askexplain this line by line. what does the first stall wait for?
  2. pokewhat happens if i delete the first stall?
  3. checkopen ttrv/ and the isa docs. was it right?
