why build it like this?

gpu

spends silicon on hiding latency for you: caches, thousands of parked warps, a scheduler. so the model stays simple: launch lots of threads

tenstorrent

spends it on sram and matrix engines, and leaves the scheduling to software. data flows tile to tile instead of round-tripping through memory

  • for brighten, honestly, the gpu is the easier tool. this chip is built for big matrix math, where planning every byte pays off
  • the payoff: blackhole-py decodes llama 3 8b (fp8, short prompts) at 81% of the card's 512 GB/s memory bandwidth, because every byte's path is planned
  • the cost: a missing wait gives a fast wrong answer, a buffer that can never be reserved hangs it. the compiler and libraries carry most people
