# 02-recall

**2:30** · three presses per task, then the comparison. keep moving: this is recall, not re-teaching

- per task: input and its **target** (green) → the network, the new piece outlined → which positions talk (recorded attention) and what the trained model did
- task 0: only the last token reaches the unembedding, so it learns "some digit", ~10% each. that's a failure by design
- task 1: same task, one head: 99.7% of the last position's attention lands on the 7
- task 2: layer 1 tags each digit with the letter before it, layer 2 looks up by that tag
- task 3: attention fetches both digits (≈48 / 51%), the mlp adds them
- task 4: two heads keep the two lookups apart, so order survives
- comparison: every model is 36 tokens in, 32-wide streams, graded only at the last position

# 03-gpu-attention

**1:45**

- step 1: one score is 32 multiplies and a sum: row = the query position, column = the source position
- step 2: all 81 are independent → parallel work. thread blocks take tiles
- step 3: memory: load a tile's rows once into shared memory, reuse them. at T = 4,096 the score matrix alone is 64 MiB per head per example
- step 4: coordination: softmax needs the whole row first; A·V waits for A
- step 5: numerics: −∞ for the future; subtract the row max or e^90 overflows
- step 6: FlashAttention: same exact math, reorganized so the T×T matrix never hits main memory. no speed numbers on purpose
- the point: the equation is three lines; doing it well on hardware is a lot of engineering

# 04-backward

**2:15** · one worked example on every stage: a2f5c9d3fc → 4, task 3's shape, **fresh** weights

- 1 embedding: ids pick rows. 2 attention: fresh weights spread evenly (compare the recorded task 3 inset, labelled)
- 3 residual: the stream is only ever added to. 4 mlp: up, relu, down, add
- 5 scores: 36 numbers, highest is "3" right now. 6 loss: −log p(4) = 3.81 for **this one prediction**; the curve is task 1's run over 1,000 updates (a different thing)
- 7 backward: chain rule, numerically, edge by edge. only 8 of 36 embedding rows get any gradient
- 8 optimizer: a separate step. Adam moves each entry by about 0.001; loss on this example 3.81 → 3.74
