how a computer executes programs

from the bottom up

note: everything is shown as x86-64 + linux, since that's what we'll be running the accelerator on.
programs are just bytes until the end, where we open them up in risc-v (what tenstorrent's cores run).

a computer is two things

a cpu (pretty dumb)

  1. read the instruction at the pc
  2. execute it
  3. move the pc to the next one (unless it jumps)
  4. repeat

who's in charge: the kernel

always there: running before your program starts and after it exits

hello world

write(1, "hello, world\n", 13);   // 1 = the terminal
exit(0);
0x10120 msg
hello,␣world\n
  1. ./hello is a file: some bytes of code, plus the 13 bytes of the message
  2. the kernel copies both into memory (msg lands at 0x10120) and starts the pc at the first instruction of the code
  3. the code puts the request in registers: write, to fd 1 (the terminal), the bytes at 0x10120, 13 of them. then it runs the syscall instruction
  4. the kernel prints it and comes back. then exit(0): another syscall, and the kernel cleans up

the actual instructions come at the end, in risc-v

// entry points here (set at boot)
syscall_entry:
    save_registers(f);
    switch (f->rax) {
    case 1:  // write
        f->rax = sys_write(f->rdi, f->rsi, f->rdx);
    case 60: // exit
        sys_exit(f->rdi);
    }
    restore_registers(f);
    sysret;                     // back to ring 3
 
sys_write(fd, buf, len):
    if (!user_memory(buf, len)) return -EFAULT;
    terminal_write(buf, len);   // device driver
    return len;
your program reaches the syscall instruction with rax = 1 (write), rdi = 1 (fd), rsi = msg, rdx = 13

all of it at once

the whole machine: the kernel holds every process, every process holds threads

reaching the card: the driver
your code calls a library. the library asks the kernel (open, ioctl, mmap), and the kernel talks to the card over pcie

opening the card

fd = open("/dev/tenstorrent/0", O_RDWR)
open the file tt-kmd made. you get an fd: every ioctl and mmap after this goes through it. close it and the driver frees everything you allocated

ask tt-kmd for a window: one of the 2 MiB slots in bar0. mmap puts it in your page table. it doesn't point anywhere yet

PIN_PAGES: the card reads your ram

buf = mmap(256 MiB)
out = ioctl(fd, PIN_PAGES, buf, 256 MiB, NOC_DMA)
out.noc_address
bulk data goes the other way round: put it in your own ram and let the card pull it (dma). buf is ordinary memory, spread over random physical pages
